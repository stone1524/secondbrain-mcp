# 路线图

## v0.1 — 2026-09（已发布）

**证明的事**：能从一个真实运行的个人系统里，把安全机制抽成带测试、带 CI 的开源工程。

- 安全三件套：哈希锁写 / 无删除归档回滚 / 隐私分区
- 关键词检索全量可用
- demo vault（合成内容）+ 快速开始文档
- pytest + ruff + GitHub Actions 全绿

## v0.2 — 2026-10（当前）

**证明的事**：检索质量可以量化验收，而且原系统的度量本身是错的——这件事能被发现、被修复、被复核。

- 单一策略源：四份互相矛盾的隐私规则合并为一处，修复大小写绕过
- 混合检索重写：RRF 取代量纲失配的 `lexical + cosine*2`
- 两道防噪门禁：语义下限 + 最小 token 数；近空桩降权
- 索引可自愈：`embed_state` 显式跟踪，失败次轮重试；模型指纹强制重建
- 正文编辑：`note_patch` 两阶段 diff 确认
- 评测重建：六类查询、dev/test 分离、四道可失败门禁
- 影子比对：新实现正确率高于被替换的旧实现，重叠度单独报告
- v0.2 补丁（schema v2–v4）：postings 丢标题、df 按行计数排序反转、中英混排/连字符词不可命中、英文文件名搜不到中文笔记、交叉引用长文压过正主（rank-1 结构性身份修复）——真实库 36 案 recall@5 0.861→1.000、recall@1 0.611→0.972，零回退；旧库自动重建
- v0.2 补丁（运维）：search 惰性重建（读不再静默清空旧库）、legacy manifest 可回滚（10/10 恢复可用）、Node 网关退役归档 + 夜间 harness 改测真实核心（healthcheck/CLI eval，暂存 state root 永不写 live 库）、依赖告警清零

## v0.3 — 按使用反馈择机

## 设计边界

以下不在路线图内，写在这里是为了避免反复讨论：

- **不引入向量数据库或 ANN 索引。** 目标规模是数千篇笔记，暴力矩阵乘在毫秒级；引入外部服务换不来可感知的收益。
- **不做本地进程鉴权或签名。** 威胁模型是 agent 误操作与内容注入，不是本地恶意进程——见 `docs/threat-model.md`。
- **不提供删除能力。** 归档 + 回滚清单是上限，物理删除永远是人的动作。
