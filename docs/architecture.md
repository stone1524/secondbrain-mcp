# 架构总览

## 总体形态

```
MCP 客户端（Claude / Cursor / 任意 agent）
        │  MCP 协议（stdio）
        ▼
┌─────────────────────────────────────────────┐
│ Gateway 工具层                               │
│  读：read_note / search_notes / rag_search   │
│      read_context(人格过滤视图)              │
│  写：create_inbox_note / append_note /       │
│      update_metadata (全部带 expected_hash)  │
│  整理：move_note / archive_notes(回滚清单)   │
├─────────────────────────────────────────────┤
│ 安全机制                                     │
│  哈希锁（乐观并发）│ 审计日志 │ 无删除设计    │
│  隐私分区（索引黑名单）│ 写入区白名单         │
├─────────────────────────────────────────────┤
│ 检索层                                       │
│  语义：embedding 索引（增量，可重建）         │
│  关键词：倒排/线性兜底                        │
│  混合排序 + 分区过滤                          │
├─────────────────────────────────────────────┤
│ 存储：纯 Markdown + frontmatter（用户可直接   │
│ 用编辑器打开，网关是唯一受控写通道）          │
└─────────────────────────────────────────────┘
```

## 设计原则

| 原则 | 含义 | 来源 |
|------|------|------|
| 文件是真相 | Vault 永远是纯 Markdown，用户可绕过网关读，但受控写只走网关 | 生产系统既定设计 |
| 乐观并发 | 写前必读，`expected_hash` 不匹配即拒绝，杜绝静默覆盖 | 生产系统既定设计 |
| 无删除 | 最危险的操作降级为「归档 + 回滚清单」；物理删除永远是人的动作 | 生产系统既定设计 |
| 索引可弃 | RAG 索引是派生物，随时 `force` 重建；真相在 Markdown | 生产系统既定设计 |
| 隐私默认黑名单 | 私有分区不进索引、不进搜索、不进人格上下文 | 生产系统既定设计 |

## 与同类项目的差异点（写简历/面试时讲这个）

- 市面上 MCP 知识库工具多数只做「读」；本项目的主张是**受控的「写」**：哈希锁 + 审计 + 无删除，让 agent 长期协作成为可能。
- 检索质量用预注册判据验收（对比实验、Recall@5 指标），方法论随文档开源。
